# Bidzaar → Telegram

Следит за публичным фидом закупок bidzaar.com и присылает в Telegram каждый
новый тендер шести медицинских организаторов, если в названии есть проектная
тематика. Работает на GitHub Actions — компьютер включать не нужно.

## Что именно отслеживается

Организаторы (фильтр по `companyId`, а не по названию — id не меняется):

| Организатор | companyId |
| --- | --- |
| МКПАО «МД Медикал Груп Инвестментс» | `019ac421-8d56-78f3-87c1-242145599e38` |
| АО «Европейский Медицинский Центр» | `5f32216f-a2ad-4e36-b7ea-66fab6b92d55` |
| ООО «Группа компаний СМ-Клиника» | `64dfa8bc-48e9-45d7-acdd-27390af78fcd` |
| АО «Медскан» | `c814b787-a771-4fed-be37-49484d5b2597` |
| Группа компаний «Медси» | `de0e84e7-e364-4f2b-a008-e005ea36e6cf` |
| INVITRO (Инвитро) | `9b3c4695-cdaa-436e-a0bf-8406fedd387a` |

Ключевые слова по названию тендера:

- `проект` — одна основа закрывает *проект*, *проектирование*, *проектная
  документация*, *проектно-изыскательские работы*. Исключение: *проектор*.
- `ПИР` — только как отдельное слово, иначе ловились бы «сп**ир**т» и «**пир**ог».
- `рабочая документация` — в любом падеже (`рабоч* документац*`).

Ожидаемый поток — 3–5 сообщений в месяц.

## Развёртывание (10 минут, бесплатно)

1. Создайте репозиторий на GitHub и загрузите туда содержимое этой папки.
2. Settings → Secrets and variables → Actions → **New repository secret**, добавьте два:
   - `TG_BOT_TOKEN` — токен бота
   - `TG_CHAT_ID` — `1793429910`
3. Settings → Actions → General → Workflow permissions → **Read and write permissions**.
4. Вкладка Actions → «Bidzaar watch» → **Run workflow**. Первый запуск молча
   запоминает текущий фид (иначе в чат сразу улетела бы вся история).
5. Дальше расписание работает само, каждые 15 минут.

Приватный репозиторий тоже подойдёт, но бесплатных минут Actions там 2000 в
месяц — при интервале 15 минут этого не хватит. Либо публичный репозиторий
(минуты не лимитированы, токен всё равно лежит в Secrets, а не в коде), либо
приватный с интервалом 30 минут.

## Локальный запуск и проверки

Зависимостей нет, нужен только Python 3.9+.

```bash
DRY_RUN=1 python bidzaar_watch.py
```

Ничего не отправляет — печатает сообщения в консоль. Полезно после правки
ключевых слов.

```bash
RESEED=1 TG_BOT_TOKEN=... TG_CHAT_ID=... python bidzaar_watch.py
```

Сбрасывает состояние на текущий фид, тоже без отправки.

## Настройка

Всё вверху [bidzaar_watch.py](bidzaar_watch.py):

- `ORGS` — организаторы. Чтобы добавить нового, найдите его `companyId`:

  ```bash
  python find_company_id.py инвитро медскан
  ```

  Скрипт ищет по последним тендерам площадки и печатает готовую строку для `ORGS`.
- `KEYWORD_RULES` — регулярки ключевых слов и подпись, которая уходит в сообщение.
- `REQUIRE_KEYWORD = False` — присылать вообще все тендеры этих организаторов
  без фильтра по словам (будет ~35 сообщений в месяц).
- `MAX_AGE_DAYS` — насколько старым может быть тендер, чтобы всё ещё считаться
  новым. Страховка: если файл состояния потеряется, в чат не уйдёт вся история.

## Как это работает

Публичный фид Bidzaar отдаётся без авторизации:

```
GET https://bidzaar.com/api/process/light/procedures/available
    ?paging.size=100&sorting.key=publishDate&sorting.direction=desc
    &logic=and&filters[0].operator=in&filters[0].field=companyId
    &filters[0].value=[<uuid>,<uuid>,...]
```

Фильтр по организаторам применяется на стороне сервера, поэтому ответ маленький.
Ключевые слова проверяются локально — так можно аккуратно обработать «ПИР» как
отдельное слово.

Уже отправленные тендеры лежат в `state/seen.json` (последние 5000 id) — файл
коммитится обратно в репозиторий, и только когда список реально изменился.
Поэтому одно и то же уведомление не приходит дважды.

Ссылка в сообщении ведёт на `https://bidzaar.com/app/process/light/<id>`.
